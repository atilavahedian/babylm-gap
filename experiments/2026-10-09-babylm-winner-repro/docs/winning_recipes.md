## Finding: AMLM's winning data is mostly MNLI/SNLI (critic, please rule)
The authors' training file (`data/bb24.train`, 10.01M words, sha256 ref-0411…) is not the official corpus. Its
first 485k lines, about 5.85M words (58%), are NLI triplets: premise, entailing hypothesis, contradicting hypothesis,
in that order. The paper cites it as the data of Zhang et al. 2023a (SynCSE), whose hypotheses were partly
generated by ChatGPT; so the non-verbatim hypotheses here may be LLM-generated text (inferred, not verified). Exact-sentence overlap (`babylm/winner/amlm/nli_overlap.py`):
- MNLI train: 99.3% of premises, 64.7% of hypotheses, 61.6% of full pairs appear verbatim. The line order encodes
  the entail/contradict label.
- MNLI validation matched/mismatched and test: about 0% of pairs (2.9% of matched premises). RTE: 0%.

The official eval fine-tunes on MNLI (and RTE, MRPC, QQP, BoolQ, MultiRC, WSC). The authors' own ablation
(paper Table 5) shows this data lifts MNLI from 47.3 to 59.1 and is where their (Super)GLUE gain comes from;
AMLM's margin over GPT-BERT (58.3 vs 57.3) is all (Super)GLUE. So the published win is plausibly the data,
not the masking. No validation/test leakage found, but this is task-training text with labels in pretraining.

## Code facts that matter for reproduction (code is ground truth over the paper)
- 12-layer DeBERTa-v2, hidden 384, FFN 1280, 34.68M params, random init from the deberta-v3-base config.
- LAMB (bitsandbytes, CUDA only) with betas (0.9, 0.98) in code (paper says 0.95); lr 7e-3, cosine, 1% warmup,
  z-loss 1e-4, whole model cast to bf16, mask-accuracy counters kept in bf16 (lossy above 256 counts).
- Sequence length 64 for epochs 0-4 then 256 (batch rows divided by 4, tokens per batch constant).
- It is a pure MLM. Critic ruling ref-0261: it cannot claim the loss leg (causal nats/word); its MLM pseudo-loss per
  word is reported as a label only. Eval uses the pipeline's `mlm` backend.
- Exposure: bb24.train is 10,009,099 words, so 10 epochs = 100.09M words, 0.09% over the strict-small cap (label arm
  only). Official train_10M = 9,953,773 words (str.split), 99.5M exposure.
- Eval tokenizer: the pipeline loads DebertaV2TokenizerFast, converted from spm.model without byte fallback (rare
  characters become [UNK]). The authors' released tokenizer.json has the same property, so our eval matches theirs.
- The authors' code saves weights only (no optimizer or RNG state); we keep it pristine and record that gap.

## Runs
Official data: `amlm/prep_official.py` builds train_10M.txt (sha256 ref-0412…), dev_small.txt (in-training eval, every
100th DEV line, 101,874 words) and train_sample_1M.txt (seed 0). Per-token saves: `amlm/per_token.py` scores every DEV
token once (7 fixed mask partitions, ~14% masked per pass) at each epoch checkpoint; float16 losses + token, line and
file ids. Labelled MLM pseudo-loss, not causal.
`babylm/winner/amlm/vm_job.sh <arm> <seed> <out>` on a GPU VM writes train.log, curve.csv, curve.png, run.json and the
BabyLM checkpoints. Cloud is blocked until the GCP key is back. CPU smoke: `babylm/winner/amlm/cpu_smoke.sh <dir> [hard_decay|hard]`
passes for both arms (4 steps, loss 10.6 -> 7.4). The whole VM job also runs on CPU with
`AMLM_CPU_TEST=1 PT_DEV_WORDS=1500 PT_TRAIN_WORDS=1500 OFFICIAL_ZIPS=<dir> bash amlm/vm_job.sh hard_decay_off 0 <out>`
(official data, tokenizer, 100-line training, checkpoints, per-token saves, run.json): passes in 6 min.
